# Продукт: экраны, виджет, уведомления, локация

## Экраны (навигация NavHost в MainActivity)

**Главный экран (Home).** Фон — динамическое небо (`SkyPalette` по WMO-коду и дню/ночи) + живой слой частиц `AnimatedSky` на Canvas поверх градиента (дождь, снег в два плана глубины — дальний мелкий чёткий + ближний крупный бледный, 140 хлопьев со сносом ветром, гроза с прорисованным зигзагом молнии (канал с ветками, неоновое свечение, двойное мерцание), туман-молоко — сплошная вуаль + крупные волны плотности, ночью вуаль тёмная, клубящиеся облака — штампы из мягкого шумового спрайта (32 цельных клуба со встречным дрейфом, без швов; днём тень серая, ночью чёрная), звёзды ночью; маппинг `skyEffectFor` — те же границы WMO). При дожде/грозе сверху лежит «мокрое стекло» `GlassRainOverlay` (слой росы + капли-бегуны с затухающими следами в отдельном битмапе) — между фоном и контентом, текст остаётся чистым. Капля объёмная из пяти слоёв без градиентов (тёмная кромка, светлая линза со сдвигом вверх, тёмный мениск снизу, светлый ободок справа, блик); крупные вытянуты вертикально, 8% росы — крупные статичные. Лимиты: десятки частиц, ~30 fps, пулы без аллокаций в кадре, вес APK не растёт. Отключение одноуровневое: тумблер «Анимация фона» в настройках (`sky_animation_enabled`, по умолчанию вкл), иначе статичный градиент. День/ночь для неба — по системным часам (`isDayNowByTime`), а не по времени замера погоды: иначе при несвежих данных утром показывается ночь. Правило: днём фон светлый, ночью тёмный — для всех типов погоды (дневные палитры облачности/дождя/грозы осветлены, днём тёмный хром только на ясном небе). Карточки — матовое стекло (`GlassCard`): тонировка от темы приложения (тёмная — в чёрное, светлая — в белое) с адаптивным текстом; хром поверх неба (топбар, заголовки, лоадер, метка обновления) — от яркости неба. Карточка текущей погоды (температура, ощущается, влажность, давление, ветер, УФ, осадки, время восхода/заката), почасовой прогноз (спарклайн температуры поверх ленты: цвет от морозно-синего до жарко-красного с порогом 0°C, линия и чипы в одном скролле, точки строго под метками времени; учитывает интервал 1/3/6 ч), недельный прогноз (7 дней: полные названия дней по локали, значок, описание бегущей строкой `basicMarquee`, если не влезает на узком экране, макс/мин, вероятность осадков, ветер через тире, УФ, восход/закат), карточка AQI (индекс + неоновая шкала с маркером + компоненты). Избранные города — свайп влево/вправо открывает диалог со списком (каждый город кнопкой, текущий залит, тап переключает); пейджера больше нет. Под топбаром мелкая метка времени последнего обновления («Погода обновлена: …»). В `actions` TopAppBar только шестерёнка настроек. Индикатор «кэшированные данные» (AssistChip). Топ-бар прозрачный: заголовок «Nimbus Weather» + кнопки. Принудительное обновление — свайп вниз (pull-to-refresh). Поиск города — из настроек («Добавить город») и с онбординга.

**Экран поиска города (LocationSearch).** Строка поиска (запрос от 2 символов, debounce 300мс), результаты геокодинга; сверху — «История поиска» (бывшие недавние) с хинтом «тыкни звёздочку, чтобы закрепить в избранном» (звёздочка — toggle в избранное, крестик — удалить из истории); у результатов поиска — `IconToggleButton` со звёздочкой (`Icons.Default.Star`/`StarBorder`, `tint = primary` когда в избранном, `contentDescription` переключается между «Добавить в избранное»/«Удалить из избранного»); клик по городу — выбор (в режиме онбординга `closeOnSelect=true` экран закрывается). Поиск мультиязычный (`WeatherRepository.searchCitiesWithFallback`): Open-Meteo ищет только на указанном языке («Харків» с language=ru даёт пусто), поэтому при пустом ответе идём по цепочке язык приложения → en → остальные наши; дубли склеиваются по id, точные совпадения поднимаются вверх через транслит (`normalizeName`, `rankResults` — «Харків» равен «Kharkiv»). Порядок избранных и удаление — только в настройках.

**Экран настроек (Settings).** Пункты:
- Единицы: °C/°F
- Тема: системная / светлая / тёмная
- Анимация фона (вкл/выкл, по умолчанию вкл) — при выключении статичный градиент
- Уведомления: тумблер вкл/выкл
- Время фонового обновления: 2 / 12 / 24 ч (WorkManager + точный будильник, см. «Фоновое обновление»); под выбором — время последнего успешного обновления («Погода обновлена: …» / «Ещё не обновлялась») и предупреждение с кнопкой, если системе запрещены точные будильники
- Интервал почасового прогноза: 1 / 3 / 6 ч
- Показ AQI (вкл/выкл) — при выключенной настройке HomeViewModel не запрашивает AQI
- Язык приложения: авто (система) / EN / UK / RU / CS — смена мгновенно, без перезапуска
- Настройка виджета (переход на WidgetCustomize)
- Добавить город (переход на LocationSearch)
- Избранные города: кнопка «+ Добавить город» под заголовком, порядок ↑/↓, удалить
- Другое: тумблер «Перезапуск при закрытии» (`KeepAliveService` — foreground-сервис, чтобы WorkManager продолжал обновлять виджет и уведомления после swipe-to-close)
- Сбросить настройки (красная кнопка + AlertDialog подтверждения)
- Внизу мелкая строка версии («Nimbus 1.x (build N)»)

**Экран настройки виджета (WidgetCustomize).** Превью в реальном времени (двухстрочное, как сам виджет); фон из палитры (авто + 9 цветов), прозрачность (слайдер 0–100%); цвет текста (авто/чёрный/белый); формат даты (числовой/текстовый); размер шрифта (50–200%, слайдер); сброс.

**Онбординг (Onboarding).** Экран приветствия: под заголовком всегда виден текущий город («Текущий город: …», по умолчанию Киев) и избранные через запятую — понятно, что выбрано; кнопка «Выбрать город» (переход в поиск, `closeOnSelect=true`) и «Начать» (пропустить — остаётся город по умолчанию). Цвета экрана согласованы с темой приложения (насыщенные, не «мышиные» — см. history).

**Экран истории погоды** — создавался в первой сессии, но удалён как лишний; в коде его нет (см. history.md).

## Город по умолчанию

- Дефолтный город (без выбора на онбординге и после сброса настроек): **Киев** (50.4501, 30.5234), таймзона `Europe/Kiev`

## Виджет (ClockTempWidgetReceiver, классические RemoteViews)

Один виджет, сетка **2×4** (`clock_temp_widget_info.xml`: minWidth 250dp, minHeight 110dp, targetCellWidth 4, targetCellHeight 2).

Композиция (`layout/widget_clock_temp.xml`): две строки, две колонки. Верхняя строка, крупно — слева текущая температура + иконка погоды (цветной вектор по WMO-коду, день/ночь по восходу/закату), справа время (TextClock «HH:mm»). Нижняя строка, мельче (0.52 от верхней) — слева иконка «человечек с градусником» (`ic_widget_feels_like`, тонируется под цвет текста) + ощущается/макс/мин (`23° ↑28° ↓16°`), справа дата (TextClock, формат — настройка: текстовый «EEE, d MMM» → «вс, 26 июл.» или числовой «dd.MM»). Градусы без буквы C/F. Время и дату отрисовывает сам лаунчер через TextClock — тикают каждую минуту даже с прибитым процессом, никакой будильник из приложения не нужен (до этого был Glance + `delay`-цикл внутри `provideContent` и AlarmManager-тикер: на MIUI часы замирали, т.к. мёртвый процесс ничего не перерисовывает). Наш код (`WidgetRemoteViews.buildWidgetViews`) обновляет только погоду, иконку, шрифты, цвета, фон и форматы: при добавлении/ресайзе виджета, при открытии приложения, при смене города/настроек и по фоновому воркеру.

Шрифты адаптивные: `fitBaseSp` бинарным поиском подбирает максимальный размер верхней строки, чтобы самая широкая из двух строк влезла в ширину из `OPTION_APPWIDGET_MIN_WIDTH` (ширина иконки погоды учитывается); размеры ставятся в px с учётом `systemFontScale * (100/widgetFontScale)`. Фон — битмап со скруглением 24dp (генерируется под фактический размер виджета). Палитра и текст — те же, что в настройках. Известное ограничение: язык даты берёт системную локаль (TextClock работает в процессе лаунчера), а не выбранный в приложении язык.

Палитра фона: «авто» (по теме) + 6 готовых цветов (белый, чёрный, синий, оранжевый, фиолетовый, сине-серый) + кнопка «+» со своим цветом (диалог с сеткой тонов 12×5, рядом серого и полем для HEX-кода, hex пишется в ту же настройку); прозрачность — слайдер 0–100% (по умолчанию 100); цвет текста — авто/чёрный/белый. Выбранный фон — `ColorDot` (сплошной круг 40dp + у выбранного белое внутреннее кольцо 28dp), вариант «авто» — иконка `BrightnessAuto`. Настройки для рендера `buildWidgetViews` читает напрямую из DataStore. Отдельного режима температуры (факт/ощущается) больше нет — виджет всегда показывает обе.

Нажатие на виджет → приложение. Погода подтягивается периодически через WorkManager и при открытии приложения; при отсутствии данных о погоде — «--°». Время/дата тикают сами (TextClock в процессе лаунчера) и от интервала обновления не зависят.

**Город виджета — первый из `favouriteCities`, иначе текущий.** `WidgetUpdateManager.updateFromTargetCity(ctx)` грузит погоду для этого города (через `WeatherRepository.getWeather`); `cachedForCity` запоминает, к какому городу относится кеш. Вызовы `updateAllWidgets(ctx, response, cityName)` сохраняют кеш только при совпадении `cityName` с целевым; иначе просто перерисовывают по имеющемуся кешу. Этот же метод вызывается после `addFavouriteCity`/`removeFavouriteCity`/`moveFavouriteCity`/`setFavouriteCities` — порядок в настройках сразу отражается на виджете.

## Уведомления

- `NotificationHelper.showWeatherNotification` — статус-бар-уведомление с температурой выбранного города; title «Сейчас 22°» (строка `weather_update_notification_title` с %1$d, в 4 локалях), contentText — описание погоды по WMO (`weatherDescriptionRes`), цвет `#1976D2`
- Показ срабатывает: при запуске приложения (bootstrapping), при фоновом обновлении, при переключении тумблера
- Канал `weather_updates` (API 26+), информер висит в шторке без звука и без повторного алерта (`setOnlyAlertOnce`), иконка из drawable, contentIntent в MainActivity
- **Android 13+ (API 33)**: `POST_NOTIFICATIONS` в манифесте + runtime-запрос в MainActivity (rememberLauncherForActivityResult) — без этого уведомление молча не показывается (см. history)

## Фоновое обновление

- `WeatherUpdateScheduler` (object внутри `service/WeatherUpdateWorker.kt`) — уникальная периодическая работа (intervalHours 2/12/24 из настроек), `ExistingPeriodicWorkPolicy.KEEP`; `reschedule` — `CANCEL_AND_REENQUEUE` при смене интервала
- `WeatherAlarmScheduler` + `WeatherAlarmReceiver` (`service/WeatherAlarm.kt`) — второй контур доставки: точный будильник (`setExactAndAllowWhileIdle`, проходит Doze) на +интервал, цепочкой (точные алармы одноразовые). При срабатывании идёт в общий `performWeatherRefresh` и планирует следующий выстрел. Нужен `SCHEDULE_EXACT_ALARM` (Android 12+): без гранта откат на неточный режим, в настройках показывается предупреждение с кнопкой перехода в системные настройки. Оба контура идемпотентны (кэш по городу)
- `performWeatherRefresh` (там же) — общая функция: погода целевого города → `WidgetUpdateManager.updateAllWidgets` → уведомление, если включены. Каждый успех пишет `lastWeatherUpdateMillis` в DataStore — время показывается в настройках под выбором интервала («Погода обновлена: …» / «Ещё не обновлялась»)
- `WeatherUpdateWorker` — тонкая обёртка над `performWeatherRefresh` (делегирует `doWork`). Читает настройки `SettingsDataStore.getHomeSettings()` одним вызовом — там и локация, и `updateIntervalHours` (TTL = `updateIntervalHours * 2`), и флаг уведомлений
- `MainActivity.onCreate` (в `lifecycleScope`, IO) читает сохранённый интервал из DataStore и ставит оба контура (периодику + будильник); заодно `WidgetUpdateManager.updateFromTargetCity` — чтобы виджеты, добавленные в прошлой сессии, подтянули погоду и актуальный фон
- `HomeViewModel.performLoad` после успешной загрузки сам зовёт `WidgetUpdateManager.updateAllWidgets` — отсюда «температура в виджете меняется сразу», а не «через цикл открытия»
- И воркер, и `HomeViewModel.performLoad` используют `SettingsDataStore.getHomeSettings()` — один `.first()` на DataStore вместо ~8 последовательных (город, координаты, таймзона, localNames, updateIntervalHours, tempUnit, useFeelsLike, hourlyIntervalHours, notificationsEnabled, appLanguage, showAqi). `getLocationSnapshot()` остался в коде как fallback, фактически не используется
- Force-stop приложения останавливает периодику до следующего явного запуска (системное ограничение Android)

## Локализация

- 4 активные локали: `values` (дефолтная папка без квалификатора — на английском, это фолбэк для любого языка, которого нет в списке ниже), `values-ru`, `values-uk`, `values-cs`. Язык приложения можно выбрать в настройках (авто/EN/UK/RU/CS). В режиме «авто» `LanguageHelper.resolveLocale` берёт язык системы: ru/uk/cs — напрямую, группа других кириллических языков (белорусский, болгарский, казахский, македонский, монгольский, сербский, таджикский, киргизский, осетинский, башкирский, чувашский, чеченский) — фолбэком на украинский, всё остальное — на английский
- Названия городов локализуются: `CityNameResolver` — ручной словарь (`KNOWN_TRANSLATIONS`, ~110 городов: столицы Европы, города Украины/РФ/Чехии) + `CityNameTranslator` (сетевой геокодинг Open-Meteo: поиск по имени на целевом языке с фильтром по координатам ±25 км, при неудаче — каскад через английское имя); переводы кешируются в `localNames` (DataStore) и дозаполняются при добавлении города, при смене языка и при старте приложения; фолбэк — name из API. Open-Meteo больше не отдаёт `local_names` в ответе геокодинга, поэтому имя в момент поиска уже локализовано (запрос на языке приложения), а переводы для остальных языков собираются дополнительными запросами
- Числа/единицы — ресурсы (m/s, hPa, °C/°F)
- Новые строки обязательно во все 4 локали, иначе Lint/красы при сборке
