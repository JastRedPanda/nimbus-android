# Продукт: экраны, виджет, уведомления, локация

## Экраны (навигация NavHost в MainActivity)

**Главный экран (Home).** Карточка текущей погоды (температура, ощущается, влажность, давление, ветер, УФ, осадки, время восхода/заката), почасовой прогноз (горизонтальная лента), недельный прогноз (7 дней: значок, день, max/min, вероятность осадков), карточка AQI (индекс по европейской шкале + 6 компонентов с подписями). Избранные города — горизонтальный pager. Переключатель городов — ряд `AssistChip` под TopAppBar, виден только когда избранных 2 и более; клик по чипу вызывает `switchToCity`, pager анимированно подтягивается к выбранной странице. На широких экранах (>=600dp) — двухколоночный планшетный лейаут (текущая погода с почасовым/AQI слева, недельный прогноз справа). Индикатор «кэшированные данные» (AssistChip). Топ-бар: заголовок «Nimbus Weather» + кнопка настроек (город — в карточке текущей погоды). Принудительное обновление — свайп вниз (pull-to-refresh). Поиск города — из настроек («Выбор города») и с онбординга.

**Экран поиска города (LocationSearch).** Строка поиска (запрос от 2 символов, debounce 300мс), результаты геокодинга; недавние города — сверху (звёздочка — в избранное, крестик — из истории); у результатов поиска — звёздочка (в избранное); клик по городу — выбор (в режиме онбординга `closeOnSelect=true` экран закрывается).

**Экран настроек (Settings).** Пункты:
- Виджет — режим температуры: фактическая / ощущается
- Единицы: °C/°F
- Тема: системная / светлая / тёмная
- Уведомления: тумблер вкл/выкл
- Время фонового обновления: 2 / 12 / 24 ч (WorkManager)
- Интервал почасового прогноза: 1 / 3 / 6 ч
- Показ AQI (вкл/выкл) — при выключенной настройке HomeViewModel не запрашивает AQI
- Язык приложения: авто (система) / EN / UK / RU / CS — смена мгновенно, без перезапуска
- Настройка виджета (переход на WidgetCustomize)
- Выбор города (переход на LocationSearch; показывается текущий город)
- Избранные города: порядок ↑/↓, удалить
- Другое: тумблер «Перезапуск при закрытии» (`KeepAliveService` — foreground-сервис, чтобы WorkManager продолжал обновлять виджет и уведомления после swipe-to-close)
- Сбросить настройки (красная кнопка + AlertDialog подтверждения)

**Экран настройки виджета (WidgetCustomize).** Превью в реальном времени: время слева, температура справа; фон из палитры (авто + 9 цветов), прозрачность (слайдер 0–100%); цвет текста (авто/чёрный/белый); формат даты (числовой/текстовый); размер шрифта (50–200%, слайдер); сброс.

**Онбординг (Onboarding).** Экран приветствия: кнопка «Выбрать город» (переход в поиск, `closeOnSelect=true`) и «Начать» (пропустить — остаётся город по умолчанию). Цвета экрана согласованы с темой приложения (насыщенные, не «мышиные» — см. history).

**Экран истории погоды** — создавался в первой сессии, но удалён как лишний; в коде его нет (см. history.md).

## Город по умолчанию

- Дефолтный город (без выбора на онбординге и после сброса настроек): **Киев** (50.4501, 30.5234), таймзона `Europe/Kiev`
- Таймзона города — из ответа геокодинга Open-Meteo (поле `timezone`), валидация `DateTimeUtils.isValidTimeZoneId` (кэширует `TimeZone.getAvailableIDs()`)
- GPS-определения города нет (было в v1.1–v1.4, удалено в v1.5 — см. history)

## Виджет (ClockTempWidget, Glance)

Один виджет, сетка **1×4** (`clock_temp_widget_info.xml`: minWidth 250dp, minHeight 40dp, targetCellWidth 4, targetCellHeight 1; описание и размер ячейки по material guidelines).

Композиция: время (часы:минуты, системная часовая зона) слева, дата по центру (формат — настройка: текстовый «d MMMM yyyy» или числовой «dd.MM.yyyy», показывается если влезает), температура справа. Шрифты адаптивные: `WidgetRender.fitBaseSp` бинарным поиском подбирает максимальный размер (10–400sp), чтобы вся строка влезла в ширину; температура — 0.92 от времени; общий размер умножается на `systemFontScale * (100/widgetFontScale)`. Описание погоды отсутствует (не помещается в высоту). Скругление углов 16dp — `androidx.glance.appwidget.cornerRadius(16.dp)` (в Glance 1.2.0-rc01 нет clip/Surface).

Палитра фона: «авто» (по теме) + 9 цветов (белый, чёрный, синий navy, морской teal, зелёный, оранжевый, фиолетовый, розовый, сине-серый); прозрачность — слайдер 0–100% (по умолчанию 100); цвет текста — авто/чёрный/белый. Выбранный фон — `ColorDot` (сплошной круг 40dp + у выбранного белое внутреннее кольцо 28dp), вариант «авто» — иконка `BrightnessAuto`. Данные для рендера собирает `WidgetRender.renderDataFlow` (combine настроек DataStore), виджет их читает через `collectAsState`. Режим температуры (факт/ощущается) — отдельная настройка в Settings.

Нажатие на виджет → приложение. Виджет пересоздаётся при смене города/настроек (sendUpdate), обновляется периодически через WorkManager; при отсутствии данных о погоде — «--°», время/дата всегда системные (`System.currentTimeMillis()`, обновление раз в 30 сек).

## Уведомления

- `NotificationHelper.showWeatherNotification` — статус-бар-уведомление с температурой выбранного города; title «Сейчас 22°» (строка `weather_update_notification_title` с %1$d, в 4 локалях), contentText — описание погоды по WMO (`weatherDescriptionRes`), цвет `#1976D2`
- Показ срабатывает: при запуске приложения (bootstrapping), при фоновом обновлении, при переключении тумблера
- Канал `weather_updates` (API 26+), информер висит в шторке без звука и без повторного алерта (`setOnlyAlertOnce`), иконка из drawable, contentIntent в MainActivity
- **Android 13+ (API 33)**: `POST_NOTIFICATIONS` в манифесте + runtime-запрос в MainActivity (rememberLauncherForActivityResult) — без этого уведомление молча не показывается (см. history)

## Фоновое обновление

- `WeatherUpdateScheduler` (object внутри `service/WeatherUpdateWorker.kt`) — уникальная периодическая работа (intervalHours 2/12/24 из настроек), `ExistingPeriodicWorkPolicy.KEEP`; `reschedule` — `CANCEL_AND_REENQUEUE` при смене интервала
- `WeatherUpdateWorker` — обновляет погоду (через `WeatherRepository.getWeather`), кэширует, дёргает `WidgetUpdateManager.updateAllWidgets` (виджет получает свежий `WeatherResponse` + сразу перерисовывается) и `NotificationHelper.showWeatherNotification` (если `notificationsEnabled`). Читает настройки `SettingsDataStore.getHomeSettings()` одним вызовом — там и локация, и `updateIntervalHours` (TTL = `updateIntervalHours * 2`), и флаг уведомлений
- `MainActivity.onCreate` (в `lifecycleScope`, IO) читает сохранённый интервал из DataStore и ставит периодику; заодно `WidgetUpdateManager.refreshAllWidgets` — чтобы виджеты, добавленные в прошлой сессии, подтянули актуальный фон
- `HomeViewModel.performLoad` после успешной загрузки сам зовёт `WidgetUpdateManager.updateAllWidgets` — отсюда «температура в виджете меняется сразу», а не «через цикл открытия»
- И воркер, и `HomeViewModel.performLoad` используют `SettingsDataStore.getHomeSettings()` — один `.first()` на DataStore вместо ~8 последовательных (город, координаты, таймзона, localNames, updateIntervalHours, tempUnit, useFeelsLike, hourlyIntervalHours, notificationsEnabled, appLanguage, showAqi). `getLocationSnapshot()` остался в коде как fallback, фактически не используется
- Force-stop приложения останавливает периодику до следующего явного запуска (системное ограничение Android)

## Локализация

- 4 активные локали: `values` (дефолтная папка без квалификатора — на английском, это фолбэк для любого языка, которого нет в списке ниже), `values-ru`, `values-uk`, `values-cs`. Язык приложения можно выбрать в настройках (авто/EN/UK/RU/CS). В режиме «авто» `LanguageHelper.resolveLocale` берёт язык системы: ru/uk/cs — напрямую, группа других кириллических языков (белорусский, болгарский, казахский, македонский, монгольский, сербский, таджикский, киргизский, осетинский, башкирский, чувашский, чеченский) — фолбэком на украинский, всё остальное — на английский
- Названия городов локализуются: `CityNameResolver` — ручной словарь (`KNOWN_TRANSLATIONS`, ~110 городов: столицы Европы, города Украины/РФ/Чехии) + `CityNameTranslator` (сетевой геокодинг Open-Meteo: поиск по имени на целевом языке с фильтром по координатам ±25 км, при неудаче — каскад через английское имя); переводы кешируются в `localNames` (DataStore) и дозаполняются при добавлении города, при смене языка и при старте приложения; фолбэк — name из API. Open-Meteo больше не отдаёт `local_names` в ответе геокодинга, поэтому имя в момент поиска уже локализовано (запрос на языке приложения), а переводы для остальных языков собираются дополнительными запросами
- Числа/единицы — ресурсы (m/s, hPa, °C/°F)
- Новые строки обязательно во все 4 локали, иначе Lint/красы при сборке
